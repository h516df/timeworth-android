# 产品草案 v0.1

## 已明确的用户需求

- 面向安卓手机。
- 用户偏好苹果式 UI / UX。
- 查看工作的时薪，将消费金额换算成工作时间。
- 纳入花呗、京东白条账单与分期相关需求。
- 从整体产品考虑功能整合，并研究现成项目以减少重复开发。
- 后续供其他人下载安装，支持应用内检查和下载更新。

下面的功能范围与迭代安排属于建议，尚未逐项定案。本文件不代表所有列出功能已经实现或承诺首版交付。

## 整体能力

| 模块 | 内容 |
| --- | --- |
| 今日概览 | 时薪、本月消费、应还、预计结余、目标进度 |
| 我的工作 | 收入、工时、加班、通勤、工作相关成本、兼职与工作对比 |
| 消费账本 | 手动记录、导入、分类、退款、报销、账户与转账 |
| 还款安排 | 信用账户、分期计划、还款日、本金、费用与剩余期数 |
| 愿望与目标 | 想买清单、购买比较、储蓄目标、购买后满意度 |
| 方案模拟 | 购买、分期、换工作、搬家、兼职与暂停工作的影响 |

## 建议的第一版

1. 工作档案与两种时薪口径。
2. 输入消费金额，实时换算对应工作时间。
3. 基础账户和账本，手动录入及经样本验证的文件导入。
4. 花呗、白条的欠款与分期记录；无法直接导入的字段允许手动补充。
5. 当月应还、预计现金流与结余，明确缺失信息和估算假设。
6. 基础愿望清单，以及购买对未来结余的简单影响预览。

## 后续候选

储蓄目标、还款提醒、工作对比、工时计时、折算收入展示、小组件、截图识别、使用成本、满意度、复杂方案模拟与可选同步。

## 计算口径

- **到手时薪**：同一周期到手收入 ÷ 实际工作时长（包含加班）。
- **详细时薪**：（同一周期到手收入 − 因工作额外产生的支出）÷（实际工作时长 + 通勤时长）。
- **消费对应工作时间**：消费金额 ÷ 所选择的时薪。
- **未来可用余额**：当前可用资金 + 预计到账收入 − 预计现金流出。
- **目标完成时间**：结合已分配资金、收入、支出与还款安排估算。

收入、支出与工时必须对应同一周期。不预设每月固定工作 22 天。奖金与其他不确定收入单独展示。分母为零、收入为负、缺少余额或计划数据时，应明确提示，不输出误导性的工时或完成日期。

“消费等价工作时间”和“多久能攒够”分开呈现。月薪制计时所得标注“折算收入”，不视为实际到账收入。历史交易保留当时的时薪口径与计算快照。

## 账单与分期

- 区分消费、归还本金、利息费用和账户转账。
- 消费记录影响消费统计；归还本金影响资金与欠款，不重复计入消费。
- 利息手续费单独记录。
- 退款关联原消费，区分申请与实际到账。
- 预测使用未来的实际现金流出，避免将同一笔信用消费及后续还款重复扣减现金。
- 导入前预览，展示新增、疑似重复、错误与待补充记录，允许编辑和排除。
- 疑似跨来源重复记录交由用户确认；不要仅因金额相同就合并交易。
- 保留导入批次和来源，提供可理解的撤销能力；存在后续修改或关联交易时提示处理影响。
- 缺少可靠关联字段时，不猜测完整的分期或还款关系。

实际导入支持范围需由脱敏样本和平台可提供的数据确定。支持信用账户不等于已经能自动获取完整历史账单及未来分期。

## 数据与体验

优先本地保存，免登录。逐步提供备份、恢复与导出。外部识别服务使用前说明发送的数据。数据缺失、空状态、无效输入和预测假设均应清晰呈现。暂缓购买只有在资金实际留存或分配到目标后才计入储蓄进度。

## 待定事项

技术栈、最低安卓版本、发布范围、许可证、备份方案，以及账单样本与接入范围。开发中的重大取舍、付费服务和授权需求须明确说明。

## 分发与更新需求

- 当前代码仓库保持私有。公开 APK、版本说明和更新元数据使用公开发布渠道，具体地址待配置。
- 用户可以检查新版本、阅读更新说明、下载 APK，并通过安卓系统完成安装确认。
- 首次正式分发前确定稳定应用包名、递增版本号和长期使用的签名密钥，验证覆盖升级与本地数据迁移。
- 签名密钥、口令和发布凭据不进入源码仓库；开发或临时调试签名不能作为长期发布密钥的替代品。
- 更新元数据与安装包通过 HTTPS 分发，下载后校验完整性，并设计失败重试和取消流程。
- 私有仓库下载不得通过在 App 中内置 GitHub 凭据的方式公开给普通用户。
